# Engineering Portfolio — Site Guide

A static, dependency-free HTML/CSS/JS portfolio for a mechanical engineer /
3D CAD designer. No build step — every file is served as-is, which makes it
straightforward to upload to Hatchable or any static host.

## File structure

```
index.html          Home — hero, about preview, featured projects, process
about.html           About — bio, philosophy, expertise, skills & software
projects.html         Projects — full case-study gallery with discipline filter
project.html          Reusable case-study template, reads ?id= from the URL
gallery.html          CAD & simulation visual gallery with lightbox
resume.html           Resume / CV page
contact.html          Contact page (social links + form)
css/styles.css         All design tokens (colors, type, spacing) + components
js/main.js             Header/footer, nav behavior, scroll reveal, lightbox
js/projects-data.js    ALL project content — edit this to change your work
js/technical-art.js    Placeholder CAD/FEA-style graphics (see below)
assets/resume-placeholder.pdf   Placeholder resume, generated by build_resume_pdf.py
build_resume_pdf.py    Script that generates the resume PDF (needs Python + reportlab)
```

## The one file you'll edit most: `js/projects-data.js`

Every project card, case-study page, and gallery image is generated from the
`PROJECTS` array in this file. To add a project, copy an existing object and
change the fields. To remove one, delete its object. Nothing else needs to
change — `project.html` builds itself from whichever project's `id` is in
the URL (e.g. `project.html?id=drone-bracket`).

Each project has:
- `summary` / `challenge` / `approach` / `cad` / `sim` — the case-study text
- `resultStats` — three short outcome stats shown as a highlight strip
- `thumb` and `gallery` — which placeholder graphics to use (see below)

## Swapping in real images

Right now every "photo" on the site is a generated SVG placeholder standing
in for CAD renders, FEA plots, and technical drawings (see
`js/technical-art.js`). This keeps the template fully self-contained with
zero external images, but you'll get a much stronger portfolio by replacing
these with real project images as soon as you have them:

1. Drop your image files into `assets/` (e.g. `assets/drone-bracket-final.jpg`).
2. In `js/projects-data.js`, add an `image` field to a project, e.g.
   `image: "assets/drone-bracket-final.jpg"`.
3. Wherever a page calls `ART.thumb(project.thumb)`, swap it for
   `<img src="${project.image}" alt="${project.title}">` once that field
   exists. The card and case-study markup already expects a block-level
   image/SVG in that slot, so no CSS changes are needed.

You do not have to convert everything at once — placeholder and real images
can coexist while you photograph/export renders project by project.

## Editing site-wide info (name, email, socials, nav)

Open `js/main.js` and edit the `SITE` object at the top — it drives the logo,
navigation links, and footer contact details across every page. The
`contact.html` page also has its own copy of the email/LinkedIn/Instagram
links in the page body; update both places to stay in sync.

## Editing the resume

- `resume.html` is the on-site CV — edit the education/experience/certifications
  directly in that file.
- `assets/resume-placeholder.pdf` is what the "Download Resume" buttons link
  to. Edit the content inside `build_resume_pdf.py` and rerun
  `python3 build_resume_pdf.py` (requires `pip install reportlab`) to
  regenerate it — or simply replace `assets/resume-placeholder.pdf` with your
  own exported PDF resume of the same filename.

## Colors & type

All design tokens live at the top of `css/styles.css` under `:root`:
dark green, graphite, charcoal, off-white, and the muted gray text color, plus
the two typefaces (IBM Plex Sans for text, IBM Plex Mono for small technical
labels). Changing a value there updates it everywhere.

## Deploying to Hatchable

This is a plain static site (HTML/CSS/JS, no build tools, no framework). Upload
the whole folder — keeping the `css/`, `js/`, and `assets/` subfolders intact —
and set `index.html` as the site's home page. If Hatchable offers its own form
handling, connect it in `contact.html`'s `<form id="contactForm">` (the JS in
`main.js` currently just shows a confirmation message locally — see the
comment above `initContactForm()`).

## Browser support

Vanilla HTML/CSS/JS, no build step, no frameworks. Uses CSS Grid, `columns`
(masonry), and `IntersectionObserver` — all well supported in current
browsers. `prefers-reduced-motion` is respected for the reveal animations.
